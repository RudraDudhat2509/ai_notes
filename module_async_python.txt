================================================================================
ASYNC PYTHON — QUICK REFERENCE
================================================================================

WHY ASYNC
---------
Blocking code waits for I/O (network/DB/disk) doing nothing.
Async suspends at await, lets event loop run other coroutines, resumes when done.
I/O-bound → async. CPU-bound → multiprocessing. Threads useless (GIL).

EVENT LOOP
----------
Single thread. Manages all coroutines.
Only one runs at any instant — but hundreds can be SUSPENDED simultaneously.
1000 users = 1000 coroutines waiting. One thread. No threads per user.
Thread = 1-8MB. Suspended coroutine = few KB. This is why it scales.

COROUTINES
----------
async def  →  function that can pause/resume
await      →  pause point. gives control to event loop. resumes when done.

TRAP — blocking inside async def:
  time.sleep(5)       →  freezes entire event loop
  requests.get(url)   →  same problem
  plain def handler   →  FastAPI moves it to thread pool (safe)

HTTPX + SHARED CLIENT
---------------------
requests = blocking sockets. Never use in async def.
httpx = non-blocking. Always use with await.

New client per request = new TCP+TLS handshake every time. Wasteful.
Shared client via lifespan = connections reused. Fast.

  @asynccontextmanager
  async def lifespan(app):
      app.state.client = httpx.AsyncClient(timeout=30.0)
      yield
      await app.state.client.aclose()

GENERATORS
----------
yield = pause, give value, resume on next().
Calling gen() returns generator object — nothing runs until next().
State (variables) preserved between next() calls.
Memory benefit: process one item at a time, not all in RAM.
async def is built on generators. await = yield to event loop.

ASYNC GENERATORS
----------------
async def + yield = streams data as it arrives.
client.post() = waits for full response. client.stream() = chunks as they arrive.
Used for LLM token streaming → user sees response word by word.

GATHER vs TASKGROUP vs QUEUE
-----------------------------
gather(return_exceptions=True)  →  fixed tasks, want all results, handle failures
TaskGroup                       →  fixed tasks, one failure cancels ALL (atomic)
Queue + N workers               →  large workload, controlled concurrency

gather default (no return_exceptions): first exception raised, others orphaned.
One None sentinel per worker (not one total) for shutdown.
task_done() required if using queue.join().

TIMEOUTS + RETRY
----------------
  async with asyncio.timeout(10):   # cancel if no response in 10s
      response = await client.get(url)
      response.raise_for_status()   # raise on 4xx/5xx

  @retry(stop=stop_after_attempt(3), wait=wait_exponential(min=1, max=10))
  Retry: 5xx, timeout, network errors. Don't retry: 404, 403, bad input.
  Failed after all retries → dead letter queue. Never silently drop.

BUGS CHEATSHEET
---------------
  time.sleep() in async def          →  asyncio.sleep()
  requests.get() in async def        →  await httpx_client.get()
  New client per request             →  shared client via lifespan
  No timeout                         →  asyncio.timeout(n)
  No raise_for_status()              →  add it after every HTTP call
  gather() no return_exceptions      →  add return_exceptions=True
  One None sentinel for N workers    →  one None per worker
  Missing task_done()                →  add after every queue.get()
  Background task uses yield-dep     →  open fresh resource inside task

INTERVIEW LINE
--------------
"Async uses coroutines on a single event loop thread. When a coroutine hits
await, it suspends and the event loop runs others. 1000 users = 1000 suspended
coroutines, not 1000 threads. Only limitation: I/O-bound only — CPU work needs
multiprocessing."
