PYDANTIC
--------
Type hints = documentation only. Pydantic = runtime enforcement.
Invalid data → ValidationError at the boundary, not deep in your code.

Coercion: "20" → 20 (str to int). Missing field → error. Wrong type → error.

Field():
  min_length, max_length       →  string constraints
  gt, lt, ge, le               →  number constraints (>, <, >=, <=)
  default=value                →  optional field
  default_factory=list         →  mutable defaults (NEVER default=[])
  exclude=True                 →  hide from serialization (API keys, secrets)
  alias="camelCase"            →  different name in JSON vs Python
  description="..."            →  LLM reads this for tool/function calling

MUTABLE DEFAULT BUG (always comes up)
  WRONG:   tools: list[str] = Field(default=[])   # shared across all instances
  CORRECT: tools: list[str] = Field(default_factory=list)
  Same for dicts: default_factory=dict

@field_validator("field_name")
@classmethod
def validate(cls, v):
    if bad: raise ValueError("msg")
    return v   # must return value. runs after type check.

@model_validator(mode="after")          # NO @classmethod here
def cross_check(self) -> "Model":
    if self.end <= self.start: raise ValueError("...")
    return self   # must return self

RULE: Field constraints → simple rules. field_validator → one field logic.
      model_validator → rules needing multiple fields.

LLM USE: Field(description="...") = what LLM reads to fill the field.
         Pydantic validates LLM output before your code touches it.

DECORATORS
----------
Function that wraps another function to add behavior.
@decorator = shorthand for func = decorator(func)

  def decorator(func):
      def wrapper(*args, **kwargs):
          result = func(*args, **kwargs)
          return result
      return wrapper   # must return wrapper

Decorator factory (takes args): @repeat(3) → repeat(3) returns decorator first.
Every level must return: outer→decorator, decorator→wrapper, wrapper→result.
Missing any return → None → TypeError when called.

FASTAPI DEPENDENCY INJECTION
-----------------------------
Shared logic (auth, DB) shouldn't be repeated in every endpoint. Use Depends().

  async def get_current_user(auth: str = Header()):
      user = decode_jwt(auth[7:])
      if not user: raise HTTPException(401)
      return user

  @app.get("/data")
  async def handler(user = Depends(get_current_user)):
      ...   # user is injected, no repetition

Composable: deps can depend on other deps. Chain stops at first failure.

yield in dependency = cleanup after request:
  async def get_db():
      async with AsyncSession(engine) as session:
          yield session   # endpoint runs here
          # session closed automatically after

BackgroundTasks = fire-and-forget after response sent:
  background_tasks.add_task(log_to_langfuse, user.id, prompt, response)
  return {"response": response}   # user gets this immediately

NEVER pass yield-based deps (DB sessions) into background tasks.
They close after the response. Task runs after. Use → closed session → crash.
Fix: open a fresh session inside the background task.

REQUEST LIFECYCLE
-----------------
1. Pydantic validates request body
2. Depends chain runs (bottom-up)
3. Endpoint runs
4. Response sent to user
5. Background tasks run
6. yield-dep cleanup runs (DB closed etc.)

BUGS CHEATSHEET
---------------
  default=[] or {}              →  default_factory=list / dict
  @classmethod on model_validator after  →  remove it
  Missing return in decorator   →  add return wrapper / return decorator
  validator not returning v     →  always return v or self
  Passing DB session to bg task →  open fresh session inside task
  No raise_for_status()         →  add after every HTTP call
