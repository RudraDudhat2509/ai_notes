JWT AUTH — QUICK REFERENCE
================================================================================

WHY JWT
-------
Passwords every request → leaks. Sessions → server storage, doesn't scale.
JWT = self-contained token. Server stores nothing. No DB lookup per request.

STRUCTURE
---------
header.payload.signature   (three base64 strings, dot-separated)

Payload contains: user_id, role, exp (expiry timestamp), type (access/refresh)
Signature = HMAC_SHA256(header + payload, SECRET_KEY)

JWT is SIGNED not ENCRYPTED. Anyone can decode payload. Never put secrets in it.
Tamper with payload → signature mismatch → rejected.

VERIFICATION (no DB needed)
----------------------------
Re-compute signature with SECRET_KEY. Matches → payload is genuine → read user_id.

ACCESS + REFRESH TOKEN PATTERN
-------------------------------
Access token   →  15 min, used for every API call, NOT stored in DB
Refresh token  →  7 days, stored in DB, only used to get new access tokens

Ban user → delete refresh token from DB → locked out in ≤15 min
No DB hit on every request. Only on token refresh (rare).

INVALID vs EXPIRED — ALWAYS DISTINGUISH
-----------------------------------------
ExpiredSignatureError  →  valid token, just old  →  tell client to REFRESH
JWTError               →  tampered/malformed     →  force RE-LOGIN

  from jose import jwt, JWTError, ExpiredSignatureError

  try:
      payload = jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
  except ExpiredSignatureError:
      raise HTTPException(401, "token expired")   # client should refresh
  except JWTError:
      raise HTTPException(401, "invalid token")   # client should re-login

Catching both as JWTError → client can't tell whether to refresh or re-login.

ALWAYS CHECK TOKEN TYPE
------------------------
  if payload.get("type") != "access":
      raise HTTPException(401, "invalid token type")
  # prevents refresh tokens being used as access tokens

SECURITY RULES
--------------
  SECRET_KEY         →  from os.environ, never hardcoded, 32+ random chars
  ANTHROPIC_API_KEY  →  separate from SECRET_KEY (different things entirely)
  Payload            →  only non-sensitive identifiers (user_id, role, exp)
  exp                →  always set. tokens without expiry = valid forever
  raise_for_status() →  always call after HTTP requests

LEAKED KEY RESPONSE
--------------------
1. Rotate key immediately (before touching git)
2. git filter-repo to remove from history
3. Force push
4. Add to .gitignore
5. Use .env pattern going forward
